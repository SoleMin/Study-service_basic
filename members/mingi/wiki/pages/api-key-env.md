# API 키 관리: .env와 .gitignore (2주차)

## 내 정리

### Q. API 키란 무엇이고, 코드에 쓰면 안 되는 이유는?

내가 사용할 모델을 호출하기 위한 일종의 열쇠, 만약 API키를 가지고 있다면 누구든지 모델을 불러쓸 수 있기 떄문에 막대한 비용이 청구될 수 있다.

따라서 보안 정책 상 API키는 코드에 작성하지 않고 별도의 파일을 두고 관리하는게 안전하다

### Q. 환경변수와 .env 파일은 무엇인가? load_dotenv()는 무엇을 하나?

env는 모델호출을 위해 필요한 API 키값, 모델 정보 등을 저장해놓는 환경변수 파일이다.

python 코드에서는 `load_dotenv()`함수 호출을 통해 env에 저장된 환경변수 값들을 불러온다.

### Q. .env, .env.example, .gitignore, .dockerignore는 각각 무슨 역할인가?

- **`.env`**: 필요한 API 키값, 모델 정보 등을 저장해놓는 환경변수 파일
- **`.env.example`**: env 형태의 뼈대가 되는 파일, 실제 API값은 비워져있고 구조만 가지고 있음
- **`.gitignore`**: github에 올라갈 때 올리지 않아야 하는 파일들을 기록하는 파일
- **`.dockerignore`**: docker 실행 시 올리지 말아야 하는 파일들을 기록하는 공간, docker의 api키값은 compose파일에서 확인한다.

### Q. Git에 안 올라가는지 어떻게 확인했나?

`git status`를 통해 실제 git에 올라가는 파일 목록들 중 ignore파일이 없는것을 확인

## Claude 피드백

- **Q1 (API 키)**: 정확해요. 덧붙이면 깃허브 공개 저장소에 올라간 키는 자동 수집 봇이 몇 분 안에 긁어 가요. 실수로 올렸다면 커밋을 지우는 것보다 **키를 즉시 폐기하고 재발급**하는 게 먼저예요.
- **Q2 (환경변수와 .env)**: 두 개를 구분하면 더 정확해요. 환경변수는 OS가 프로세스에 넘겨주는 `KEY=VALUE` 값이고, `.env`는 그 값을 적어 둔 텍스트 파일일 뿐이에요. `load_dotenv()`가 `.env`를 읽어 `os.environ`에 넣고, 코드는 `os.getenv("GEMINI_API_KEY")`로 꺼내 써요. 이미 설정된 환경변수는 기본으로 덮어쓰지 않아요.
- **Q3 (.dockerignore 수정)**: `.dockerignore`는 "실행 시"가 아니라 **`docker build` 때 이미지 안으로 보내지 않을 파일** 목록이에요. 여기에 `.env`가 있어야 `COPY . .`를 해도 키가 이미지 레이어에 구워지지 않아요. 컨테이너가 키를 받는 건 실행 시점에 compose의 `env_file`이 넣어 주는 거라, 이미지에는 키가 없어요.
- **Q4 (확인 방법)**: `git status`도 좋고, `git check-ignore -v .env`를 치면 어느 `.gitignore`의 몇 번째 줄 때문에 무시되는지까지 보여 줘요. 주의할 점: 이미 한 번 커밋된 파일은 `.gitignore`에 적어도 계속 추적돼요. 그때는 `git rm --cached .env`가 필요해요.
- 이번 주에 파일 이름이 `env`(점 없음)였을 때 무시도, 로드도 안 됐던 경험을 "내가 막힌 점"에 적으면 좋은 사례가 돼요.
