# 4주차 과제 가이드: RAG 고도화 + API화

목표는 세 가지예요. 3주차 RAG의 검색 점수를 기법 하나로 올려 보고, 그 RAG를 FastAPI `/ask`로 감싸고, Docker 이미지로 빌드해요. 단체 세션에서는 기준선 대비 점수를 표에 적어 비교해요(검색 품질 대회).

## 0. 시작 전에 알아 둘 것

**기준선이 바뀌었어요.** 3주차 기준선(Recall@5 1.000, MRR@5 0.823)은 페이지 15개, 질문 25개로 잰 값이에요. 지금 팀 위키는 31개 페이지라 같은 설정으로 다시 재야 대회 비교가 공정해요.

**질문셋에 3주차 페이지가 없어요.** 질문 25개는 1~2주차 페이지만 정답으로 가져요. 3주차 RAG 페이지 15개용 질문 초안을 `4주차_질문셋_초안.jsonl`에 13개 만들어 뒀어요. 팀 공통 파일이라 단체 채팅방에서 "추가해도 되는지" 먼저 확인하고 넣는 걸 권해요. 다른 팀원이 이미 25개로 쟀다면, 25개와 38개 점수를 둘 다 적으면 돼요.

**중복 주제 페이지는 남기기로 했어요.** 질문셋은 정답 페이지를 여러 개 적을 수 있어서(그중 하나만 찾아도 정답) 채점은 문제없어요. 대신 같은 주제 페이지끼리 1위를 다투니 MRR이 낮게 나오는 원인이 계속 남아요. 3주차에 1위를 놓친 8개 질문이 대부분 이 경우였어요.

## 1. 기법 고르기: 리랭커를 추천해요

| | 하이브리드 (BM25 + 벡터, RRF) | 리랭커 (크로스인코더) |
| --- | --- | --- |
| 무엇을 고치나 | 못 찾는 문서를 찾게 함 (Recall) | 찾은 문서의 순서를 바로잡음 (MRR) |
| 강한 경우 | 고유명사, 숫자, 명령어(`-v`, `EX 60`) | 표현은 다른데 뜻이 같은 질문, 비슷한 페이지끼리 순위 다툼 |
| 비용 | 거의 없음 (BM25는 가벼움) | 후보 20개를 모델로 다시 채점해서 지연이 늘어남 |
| 주의 | 한국어는 띄어쓰기 단위로 자르면 "컨테이너가", "컨테이너를"이 다른 단어가 됨 | 모델 `BAAI/bge-reranker-v2-m3` 약 2GB 추가 다운로드 |

3주차 결과에서 Recall은 이미 1.000이고 약점은 MRR(1위를 놓친 질문 8개)이었어요. 그래서 순위를 고치는 **리랭커**가 효과를 보기 쉬워요. 1일차에 31개 페이지로 다시 쟀을 때 Recall이 많이 떨어졌다면 하이브리드가 더 맞을 수 있으니, 그때 다시 골라요.

### 과정 7. `/ask` API (3일차, 60분)

할 일
