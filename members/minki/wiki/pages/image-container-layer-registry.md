# 이미지, 컨테이너, 레이어, 레지스트리

**한 줄 정의**: Dockerfile(레시피)로 빌드한 완성품이 이미지(밀키트)이고, 이미지를 실행한 프로세스가 컨테이너(요리)예요. 이미지는 읽기 전용 레이어를 쌓아 만들고, 레지스트리에 올려 공유해요.

## 왜 필요한가

내 PC에서 돌던 코드를 다른 PC, 서버, k8s에서도 똑같이 돌리려면 코드와 라이브러리, OS 파일까지 한 덩어리로 묶어서 옮겨야 해요. 그 덩어리가 이미지예요.

- **이미지**: 실제 파일, 라이브러리, 코드와 실행 설정이 든 완성품. 설명서는 이미지가 아니라 Dockerfile이에요.
- **컨테이너**: 이미지를 실행한 프로세스. 호스트 커널을 공유하면서 프로세스, 파일시스템, 네트워크만 격리해요.
- **레이어**: Dockerfile 명령 하나가 읽기 전용 레이어 하나가 돼요. 레이어는 이미지끼리 공유되고 빌드 캐시로 재사용돼요. 컨테이너를 띄우면 그 위에 얇은 쓰기 레이어가 올라가서, 컨테이너 안에서 바꾼 것은 이미지에 남지 않아요.
- **레지스트리**: 이미지 저장소. 레지스트리(Docker Hub) > 레포지토리(nginx) > 태그(nginx:1.27) 순으로 묶이고, 태그가 버전을 구분해요.

## 최소 예제

```bash
docker pull python:3.11-slim        # 레지스트리에서 이미지 받기
docker images                       # 로컬 이미지 목록
docker run --rm python:3.11-slim python -c "print('hi')"   # 이미지로 컨테이너 실행
docker history python:3.11-slim     # 이미지를 이루는 레이어 보기
docker rmi python:3.11-slim         # 이미지 삭제 (삭제할 수 있어요)
```

## 내가 막힌 점

- 처음엔 이미지를 "설명서"로, 레이어를 "이미지는 삭제가 안 돼서 덧붙이는 방식"으로 이해했어요. 설명서는 Dockerfile이고, 이미지는 `docker rmi`로 지울 수 있어요. 레이어의 핵심은 읽기 전용이라 캐시와 공유가 된다는 점이에요.
