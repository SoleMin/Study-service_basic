# 2주차 과제 가이드: FastAPI + docker compose

## 이번 주에 만드는 것

네 항목은 따로따로가 아니라 **하나의 작은 LLM 서버를 단계별로 키우는 과정**이에요.

```
① FastAPI 기본기        → 서버가 요청을 받고 응답하는 구조 익히기
② /chat (LLM 호출)      → 그 서버가 LLM을 대신 불러 주는 API가 됨
```

## ① GET, POST 엔드포인트와 Pydantic 모델, `/docs`에서 호출

### 뭘 하라는 건지

- **엔드포인트**: 서버의 "창구"예요. `GET /health`는 "상태 알려줘", `POST /echo`는 "이 데이터 처리해 줘" 같은 창구 하나하나예요.
  - **GET**: 데이터를 가져오기만 할 때 (주소창에 쳐서 열 수 있음)
  - **POST**: 요청에 데이터(JSON 본문)를 실어 보낼 때
- **Pydantic 모델**: "요청은 이런 모양이어야 한다"를 클래스로 적어 두는 것. 모양이 틀린 요청(필드 빠짐, 타입 틀림)은 FastAPI가 알아서 422 에러로 막아 줘요.
- **`/docs`**: FastAPI가 자동으로 만들어 주는 테스트 화면(Swagger UI). 코드를 따로 안 짜도 브라우저에서 버튼으로 API를 호출해 볼 수 있어요.

### 해 볼 것

```bash
pip install fastapi uvicorn
```

```python
# app/main.py
from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class EchoRequest(BaseModel):
    message: str
    repeat: int = 1          # 기본값이 있으면 생략 가능

class EchoResponse(BaseModel):
    result: str

@app.get("/health")
def health():
    return {"status": "ok"}

@app.post("/echo", response_model=EchoResponse)
def echo(req: EchoRequest):
    return EchoResponse(result=req.message * req.repeat)
```

```bash
uvicorn app.main:app --reload
```

브라우저에서 `http://127.0.0.1:8000/docs` → `POST /echo` → "Try it out" → 본문을 넣고 Execute.

## ② LLM API를 호출하는 `/chat`, API 키는 `.env`로 관리

### 뭘 하라는 건지

- `/chat`에 질문을 POST로 보내면, 서버가 LLM API(Claude, OpenAI 등)를 대신 호출해서 답을 돌려주는 엔드포인트를 만들어요. 사용자는 API 키 없이 내 서버만 부르면 돼요.
- **API 키는 코드에 직접 쓰지 않아요.** 코드에 쓰면 GitHub에 올라가는 순간 누구나 내 돈으로 API를 쓸 수 있어요. 그래서
  - `.env` 파일에 키를 두고, 코드는 환경변수로 읽어요
  - `.gitignore`에 `.env`가 있어서 Git에 안 올라가요 (팀 저장소 뼈대에 이미 들어 있어요)
  - 팀원에게는 키 이름만 적힌 `.env.example`을 공유해요

### 해 볼 것

```bash
pip install anthropic python-dotenv
```

```
# .env  (절대 커밋하지 않기)
ANTHROPIC_API_KEY=sk-ant-...
```

```python
# app/main.py 에 추가
from dotenv import load_dotenv
from anthropic import AsyncAnthropic

load_dotenv()                  # .env를 읽어 환경변수로 등록
client = AsyncAnthropic()      # ANTHROPIC_API_KEY 환경변수를 자동으로 읽음

class ChatRequest(BaseModel):
    question: str

class ChatResponse(BaseModel):
    answer: str

@app.post("/chat", response_model=ChatResponse)
async def chat(req: ChatRequest):
    response = await client.messages.create(
        model="claude-opus-5-5",
        max_tokens=16000,
        messages=[{"role": "user", "content": req.question}],
    )
    answer = "".join(b.text for b in response.content if b.type == "text")
    return ChatResponse(answer=answer)
```

OpenAI 키를 쓰면 `openai` 패키지로 같은 구조를 만들면 돼요. 팀에서 같은 걸 쓰면 코드 리뷰 때 비교하기 쉬워요.


## ③ FastAPI + Redis를 docker compose로 띄우고, TTL 캐시로 속도 비교

### 뭘 하라는 건지

세 가지 개념이 합쳐져 있어요.

- **docker compose**: 컨테이너 여러 개를 YAML 파일 하나로 같이 띄우는 도구. 1주차엔 `docker run`을 하나씩 쳤다면, 이제 "FastAPI 서버 + Redis"를 `docker compose up` 한 번으로 띄워요.
- **Redis**: 메모리에 키-값을 저장하는 아주 빠른 DB. 여기서는 "질문 → 답"을 저장하는 캐시로 써요.
- **TTL(Time To Live)**: 저장한 값의 유효기간. 예를 들어 1시간이 지나면 자동으로 지워져서 오래된 답이 계속 나가지 않게 해요.

흐름은 이래요.

```
질문 도착 → Redis에 같은 질문이 있나?
   ├─ 있음(캐시 히트)  → 바로 반환 (수 ms)
   └─ 없음(캐시 미스) → LLM 호출 (수 초) → Redis에 TTL 걸고 저장 → 반환
```

LLM 호출은 느리고 돈이 들어서, 같은 질문에 다시 돈과 시간을 쓰지 않게 하는 거예요.

### 해 볼 것

```
# requirements.txt
fastapi
uvicorn
anthropic
python-dotenv
redis
```

```python
# app/main.py 의 /chat을 캐시 버전으로
import os, time, hashlib
import redis.asyncio as redis

r = redis.Redis(host=os.getenv("REDIS_HOST", "localhost"), port=6379, decode_responses=True)
CACHE_TTL = 3600  # 초

class ChatResponse(BaseModel):
    answer: str
    cached: bool
    elapsed_ms: float

@app.post("/chat", response_model=ChatResponse)
async def chat(req: ChatRequest):
    start = time.perf_counter()
    key = "chat:" + hashlib.sha256(req.question.encode()).hexdigest()

    if (hit := await r.get(key)) is not None:
        return ChatResponse(answer=hit, cached=True,
                            elapsed_ms=(time.perf_counter() - start) * 1000)

    response = await client.messages.create(
        model="claude-opus-5-5",
        max_tokens=16000,
        messages=[{"role": "user", "content": req.question}],
    )
    answer = "".join(b.text for b in response.content if b.type == "text")
    await r.set(key, answer, ex=CACHE_TTL)   # ex = TTL(초)
    return ChatResponse(answer=answer, cached=False,
                        elapsed_ms=(time.perf_counter() - start) * 1000)
```

```dockerfile
# Dockerfile (1주차와 같은 패턴: requirements 먼저 → 캐시 활용)
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app/ app/
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

```yaml
# docker-compose.yml
services:
  api:
    build: .
    ports:
      - "8000:8000"        # 1주차의 -p 와 같은 것
    env_file: .env         # 키는 .env에서 주입 (이미지 안에 넣지 않음)
    environment:
      REDIS_HOST: redis    # ← 서비스 이름으로 접속!
    depends_on:
      - redis
  redis:
    image: redis:7
```

```bash
docker compose up --build
```

핵심 포인트: FastAPI 컨테이너 안에서 `localhost`는 자기 자신이라 Redis가 없어요. compose는 서비스 이름(`redis`)을 주소로 쓸 수 있게 해 줘서 `REDIS_HOST=redis`로 접속해요. 통합 체크리스트의 개인 추가 항목 "컨테이너끼리 서비스 이름으로 통신하는 원리"가 바로 이거예요.

### 속도 비교

`/docs`에서 같은 질문을 두 번 보내고 `elapsed_ms`와 `cached`를 비교해요.

| 호출 | cached | elapsed_ms |
| --- | --- | --- |
| 1번째 | false | (예: 3000~10000) |
| 2번째 | true | (예: 1~5) |

TTL 확인: `docker compose exec redis redis-cli TTL chat:<키>` 로 남은 초가 줄어드는 걸 볼 수 있어요. 키 목록은 `redis-cli KEYS "chat:*"`.

## ④ async 함수가 언제 필요한지 위키 페이지로 정리

### 뭘 하라는 건지

②③에서 `def` 대신 `async def`와 `await`를 썼어요. 그 이유를 직접 확인하고 `wiki/pages/async-fastapi.md`로 정리하는 거예요 (페이지 템플릿: 한 줄 정의, 왜 필요한가, 최소 예제, 막힌 점, 출처).

정리할 핵심은 이 정도예요.

- LLM 호출, DB, Redis, 다른 API 호출처럼 **기다리는 시간이 대부분인 작업(I/O)**은 `async def` + `await`가 이득이에요. 기다리는 동안 서버가 다른 요청을 처리할 수 있어요.
- `async def` 안에서 **동기 함수로 오래 기다리면(예: `time.sleep`, 동기 `requests`) 서버 전체가 멈춰요.** async 안에서는 async 라이브러리(`AsyncAnthropic`, `redis.asyncio`, `httpx`)를 써야 해요.
- 모델 추론이나 큰 계산처럼 **CPU를 계속 쓰는 작업**은 async로 빨라지지 않아요. 그냥 `def`로 쓰면 FastAPI가 별도 스레드에서 돌려 줘요.

### 직접 확인하는 실험 (10분)

```python
import asyncio, time

@app.get("/sync-sleep")
def sync_sleep():
    time.sleep(3)
    return {"ok": True}

@app.get("/async-sleep")
async def async_sleep():
    await asyncio.sleep(3)
    return {"ok": True}

@app.get("/bad-sleep")
async def bad_sleep():
    time.sleep(3)        # async 안에서 동기 대기 → 서버가 멈춤
    return {"ok": True}
```

브라우저 탭 3개에서 `/async-sleep?n=1`, `?n=2`, `?n=3`처럼 주소 끝을 조금씩 바꿔 거의 동시에 열고 걸린 시간을 비교해요. (주소가 완전히 같으면 브라우저가 알아서 하나씩 보내서 실험이 안 돼요.) `/async-sleep`과 `/sync-sleep`은 셋 다 약 3초(`def`는 FastAPI가 별도 스레드에서 돌려 줘서), `/bad-sleep`만 3초, 6초, 9초처럼 줄을 서요. 이 결과를 위키 페이지의 "최소 예제"에 넣으면 돼요.
