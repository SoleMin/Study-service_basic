# HyDE

## 한 줄 정의

질문으로 바로 검색하지 않고, LLM이 먼저 "답변처럼 생긴 가짜 문서"를 써 보게 한 뒤 그 문서로 검색하는 기법이다. HyDE는 Hypothetical Document Embeddings의 줄임말이다.

## 왜 필요한가

임베딩 검색은 질문 벡터와 가까운 문서 벡터를 찾는다. 그런데 질문과 위키 문서는 모양이 많이 다르다.

| | 질문 | 위키 문서 |
|---|---|---|
| 길이 | 짧음 | 김 |
| 문체 | 의문문 | 설명문 |
| 용어 | 일상어 ("실행 단위") | 전문 용어 ("컨테이너", "이미지 레이어") |

가짜 문서는 위키 문서와 문체와 용어가 비슷해서, 질문보다 정답 문서에 더 가까운 벡터가 나올 수 있다. 가짜 문서의 내용이 틀려도 괜찮으며, 검색에만 쓰고 최종 답변에는 쓰지 않는다.

잘 되는 경우는 질문이 짧거나 모호할 때, 질문과 문서의 용어가 다를 때다. 안 되는 경우는 LLM이 위키에 없는 내용을 엉뚱하게 지어내서 검색이 다른 주제로 끌려갈 때다.

## 예제

### 흐름

```
질문: "도커의 실행 단위는?"
   ↓ LLM이 가짜 답변 문서 작성
"도커의 기본 실행 단위는 호스트의 커널을 공유하며 독립된 프로세스로 구동되는
 컨테이너(Container)입니다. docker run 명령어로 이미지(Image)로부터 ..."
   ↓ (질문 + 가짜 문서)를 bge-m3로 임베딩
   ↓ Chroma에서 k=5 검색
정답 위키 페이지 검색
```

변형은 두 가지를 비교했다.
- **HyDE(가짜만)**: 가짜 문서만 임베딩해서 검색
- **HyDE(질문+가짜)**: 원래 질문 뒤에 가짜 문서를 붙여 임베딩해서 검색

가짜 문서를 만드는 프롬프트는 다음과 같다.

```python
HYDE_PROMPT = ChatPromptTemplate.from_template(
    "당신은 쿠버네티스, Docker, FastAPI, RAG를 다루는 기술 위키 작성자입니다.\n"
    "아래 질문에 답하는 위키 문서의 한 단락(3~5문장)을 한국어로 쓰세요.\n"
    "- 질문과 관련된 전문 용어와 명령어를 포함하세요.\n"
    "- 확실하지 않아도 그럴듯하게 쓰세요. 정확성보다 용어가 중요합니다.\n"
    "- 인사말이나 '질문에 답하자면' 같은 말은 쓰지 마세요.\n\n"
    "질문: {question}"
)
```

```python
class HyDERetriever(BaseRetriever):
    base_retriever: BaseRetriever
    hyde_chain: object
    include_query: bool = True

    def _get_relevant_documents(self, query, *, run_manager=None):
        fake = self.hyde_chain.invoke({"question": query})
        text = f"{query}\n{fake}" if self.include_query else fake
        return self.base_retriever.invoke(text)
```

### 평가 결과

평가 조건은 다음과 같다.
- 팀 평가 기준: 임베딩 bge-m3, chunk_size=500, chunk_overlap=50, 벡터 검색 k=5
- 팀 위키 문서 33개, 청크 198개
- 질문 25개 (`team/eval/questions.jsonl`), 정답은 `answer_pages` 기준
- LLM: gemini-3.5-flash-lite
- 1회 측정 (LLM 출력이 매번 달라서 값이 조금씩 변동됨)

| 기법 | Recall@5 | MRR@5 | 응답시간(질문당) | 기준선 대비 질문별 변화 |
|---|---|---|---|---|
| 기준선 | 0.960 | 0.800 | 0.24초 | - |
| 리랭커 | 1.000 | 0.825 | 21.38초 | 4개 개선, 3개 악화 |
| HyDE(가짜만) | 0.960 | 0.873 | 5.84초 | 5개 개선, 2개 악화 |
| HyDE(질문+가짜) | 1.000 | 0.870 | 4.88초 | 4개 개선, 2개 악화 |
| HyDE+리랭커 | 1.000 | 0.857 | 22.84초 | 4개 개선, 3개 악화 |

해석은 다음과 같다.
- **HyDE(질문+가짜)**가 가장 균형이 좋았다. 모든 질문에서 정답이 5위 안에 있고(Recall 1.000), MRR이 +0.070 올랐다. 응답은 약 5초로 기준선의 20배다.
- **HyDE(가짜만)**는 MRR이 가장 높지만 Recall이 그대로이고, "컨테이너 안에서 8888번으로 돌아가는 서비스…" 질문이 3위에서 5위 밖으로 떨어졌다. 가짜 문서가 엉뚱하게 나오면 위험하다.
- **리랭커**는 MRR이 +0.025 올랐지만 응답이 21초로 약 90배 느려진다. 팀 채택 규칙(늘어난 시간을 감수할 만할 때만)에 맞지 않아서 제외했다.
- HyDE에 리랭커를 더해도 HyDE 단독보다 나아지지 않아서 제외했다.

질문별로 눈에 띈 사례는 다음과 같다.
- 기준선이 5위 밖(X)이던 "이미지를 만들 때 실행되는 명령과…"는 HyDE와 리랭커 모두 1위가 되었다. 표현이 달라서 못 찾던 유형이다.
- "이미지와 컨테이너를 설계도에 비유하면…"은 기준선 3위에서 HyDE(가짜만) 1위로 올랐다.
- "컨테이너가 꺼진 뒤에도…"는 리랭커만 1위에서 5위로 떨어졌다.
- "컨테이너 안에서 8888번으로 돌아가는 서비스…"는 어떤 기법으로도 해결되지 않았다.

기준선이 이미 1위인 질문이 25개 중 18개라서 점수 차이는 몇 개 질문에서 나온다. 따라서 평균 점수의 작은 차이(예: MRR 0.870과 0.873)는 오차 범위로 봐야 한다.

팀 프로젝트 채택 후보는 **HyDE(질문+가짜)**다. 반복 측정 결과는 측정 예정이다.

## 내가 막힌 점

- **점수가 매번 달라진다.** 사용한 모델이 `temperature`를 무시한다는 경고(`the sampling parameter(s) temperature will be ignored`)가 뜬다. 그래서 같은 질문에도 가짜 문서가 달라지고, 점수도 실행마다 조금씩 변한다. 첫 5개 질문으로 돌렸을 때 HyDE(질문+가짜)의 첫 질문이 5위 밖이었는데, 25개로 돌렸을 때는 2위였다. 반복 측정해서 평균을 내야 한다(측정 예정).
- **개선이 몇 개 질문에 몰려 있다.** 기준선이 이미 1위인 질문이 많아서 개선 여지가 있는 질문이 적다. 이 점수 차이를 얼마나 믿어야 하는지 판단하기 어렵다.
- **리랭커가 일부 질문에서 오히려 나빠진 이유를 아직 모른다.** 특히 "컨테이너가 꺼진 뒤에도…"가 1위에서 5위로 내려갔는데, 어떤 청크가 올라왔는지 아직 확인하지 못했다.
- **"8888번 서비스" 질문이 모든 기법에서 안 풀리는 이유를 아직 모른다.** 청킹 문제인지, 문서에 해당 내용이 부족한지 확인이 필요하다.
- **채점 기준이 팀 `evaluate.py`와 완전히 같은지 확인하지 못했다.** 내 스크립트는 정답 페이지 중 하나라도 5위 안에 있으면 맞은 것으로 채점하고, 순위는 가장 높게 나온 정답 페이지 기준이다.
