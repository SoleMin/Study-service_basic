# 컨테이너 관리 명령어 (1주차)

## 내 정리

### Q. docker ps, logs, exec, stop, rm은 각각 무엇을 하나? 실제로 언제 썼나?

- **`docker ps`**: 지금 실행 중인 컨테이너 목록확인 (`-a`: 종료된것 까지 확인)
- **`docker logs <이름>`**: 컨테이너가 출력한 로그확인. 학습 진행 상황이나 에러 확인용 (`-f`면 실시간)
- **`docker exec -it <이름> bash`**: 실행 중인 컨테이너 안에 들어가서 명령어 실행
- **`docker stop <이름>`**: 컨테이너를 종료
- **`docker rm <이름>`**: 꺼진 컨테이너를 삭제

1주차에서 학습 컨테이너 로그를 볼 때 logs, 안에 파일이 생겼는지 확인하기 위해 exec사용

### Q. --name, -d, --rm은 무엇을 하나?

- **`--name`**: 컨테이너 실행시 이름을 지정해줌, 지정해주지않으면 랜덤 이름이 붙어 찾기가 힘들어짐
- **`-d`**: 백드라운드 실행용, 바로 프롬포트로 돌아오게됨
- **`--rm`**: 종료시 자동으로 rm을 하게 하는 역활, 자동으로 삭제시킴

### Q. 이미지와 컨테이너를 명령어로 구분하면? (docker images vs docker ps -a)

이미지는 컨테이너를 띄우기 위한 설계도

컨테이너는 이미지를 통해 만들어진 실제 무언가

- **`docker images`**: 내 PC에 있는 이미지 목록
- **`docker ps -a`**: 그 이미지로 띄웠던 컨테이너 목록

## Claude 피드백

- **Q1**: 다섯 개 모두 정확하고, 실제로 쓴 상황까지 적은 게 좋아요. 보태면 `exec`는 **실행 중인** 컨테이너에만 들어갈 수 있어요(꺼진 컨테이너는 에러). `stop`은 앱에 "정리하고 꺼라" 신호를 보내고, 10초 안에 안 꺼지면 강제로 꺼요. `rm`은 실행 중인 컨테이너엔 거부되고, `docker rm -f`를 쓰면 끄고 지우기를 한 번에 해요.
- **Q2**: 정확해요. 두 가지 팁을 보태면:
  - `-d`로 띄우면 출력이 화면에 안 나오니, 그때 `docker logs -f <이름>`으로 따라가요. 그래서 `-d`와 `--name`은 보통 같이 써요.
  - `--rm`으로 띄운 컨테이너는 끝나면 안에 만든 파일도 같이 사라져요. 학습 결과를 남기려면 `-v`로 내 PC 폴더에 저장해야 해요(volume-port 페이지와 연결).
- **Q3 (용어 맞추기)**: 1주차 피드백에서 정리한 것처럼 "설계도"는 Dockerfile이고, 이미지는 그걸로 빌드한 **완성품**(밀키트), 컨테이너는 그 완성품을 실행한 것(요리)이에요. 이 페이지도 "이미지 = 설계도"보다 "이미지 = 실행할 수 있는 완성품"으로 맞추면 다른 페이지와 일관돼요.
- **Q3 (명령어)**: 정확해요. 둘의 관계가 보이는 지점은 이미지 하나로 컨테이너를 여러 개 띄우면 `docker ps -a`에 같은 IMAGE 이름이 여러 줄 나온다는 점, 그리고 컨테이너가 남아 있으면 `docker rmi`가 거부돼서 `docker rm`을 먼저 해야 한다는 점이에요.
